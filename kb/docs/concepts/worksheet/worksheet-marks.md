# Worksheet marks — Marks card, member colours, table look

What each Marks slot accepts and how it renders, plus member colours and the palette. Part of the worksheet encodings ([worksheet-encodings.md](worksheet-encodings.md)); base worksheet: [worksheet.md](worksheet.md). The Colour channel's newer behaviour (several measures, Automatic scale, opacity, several fields, pie split) is in [worksheet-marks-colour.md](worksheet-marks-colour.md); Shape (a measure on Shape, member shapes) and Label marks are in [worksheet-marks-shape-label.md](worksheet-marks-shape-label.md).

## Marks slots

The Marks group sits at the top of the field pane and collapses like the other groups. Its open or collapsed state is remembered per browser (`dashboardbuilder.marks.pref`); with nothing remembered it starts collapsed only while no slot is set, and an open editor keeps it open. Collapsed, its header shows a one-line summary of the slots in use ("Color, Detail (2)"). It is a grid of **three columns** of slots: Color, Size, Label, Detail, Tooltip, Shape, Path, Angle, Filters, Date range, Drill, Pages.

- **Every tool is always reachable** (there is no More menu). Tools the chart type doesn't use are **quiet** (dimmed) unless they hold fields or their flyout has a control for the chart type ([D155](../../decisions/decisions-marks.md#d155--every-marks-tile-opens-its-own-controls-the-color-flyout-generalised)): Size on every sized chart type and on a treemap, Text or Table with a Size field (so it is quiet only on a histogram, a square heatmap and KPI without one); Shape outside scatter, square, circle; Path outside line, area; Angle outside pie, donut; Detail, Drill and Pages by default. Marker size lights Size on a circle heatmap, Marker shape lights Shape on a line, area or combo, and Line style lights Path on a combo.
- **A slot** is an icon over its name, 65px × 50px with 8px of padding on every side and 4px between slots. It shows a **count badge** when it holds fields, riding the slot's top-right corner (half a gap outside it, so a two-digit count never reaches the icon), and is a **drop target** (drag a field straight onto it). The slot's long hint (what it accepts) is its `title`; a tile that holds nothing shows no dashed zone: the slot is the Drop Field Here row alone (the whole slot still takes a dropped field).
- **Click a slot** to open **one** editor, with its pills over a drop zone. It is a **flyout** (`.ws-toolfly`) that opens just right of the field pane, level with the slot but below the Columns and Rows lanes, so a field is one short drag away, the chart never shifts, and the lanes stay uncovered. At most one editor is open at a time.
  - Keyboard focus moves into the flyout when a slot is pressed; **Esc** or ✕ closes it and returns focus to the slot. Pressing the slot again also closes it.
  - Pressing the chart puts the flyout away (the press still reaches the chart); the field pane, lanes and the flyout itself are left alone, since fields are dragged from and to them.
  - Each editor has a **Drop Field Here** row until it holds a field, then only the pills' dashed zone: the row is the place a dragged field lands, not a button. There is no field list, so hover and click open nothing; fields come from the field pane by drag and drop onto the slot or the tile ([D156](../../decisions/decisions-marks.md#d156--the-drop-field-here-row-takes-a-dropped-field-only-there-is-no-field-list)). The slot's own drop handler applies the rules and messages (Date range takes a temporal field; Size takes any field). In every flyout it is its own full-width row ([worksheet-marks-colour.md](worksheet-marks-colour.md#the-color-flyout)).
  - The flyout reads as stacked sections (a recessed title band, the slot, then the editor's groups), each split from the next by a full-width hairline, lifted off the chart by a soft shadow ([layout.md](../../reference/design/layout.md)). The slot, what the tool holds, opens the first section of the tile's editor (**Date range**: full-width range and compare selects; **Tooltip**: the whole editor, [D173](../../decisions/decisions-marks.md#d173--the-edit-tooltip-editor-moves-into-the-tooltip-flyout-and-commits-live)), and stays a section of its own above **Filters**, whose filter cards (values, bounds, checklists) are repeated in the flyout while it is open so they are never hidden behind it (the header's copy stays invisible and inert, keeping its height, so the chart does not shift). **Section titles are shown only where a section is not named by its own controls**, and only in a flyout with two or more sections (the title band names a lone one): the Label card titles Label Appearance, Marks to Label and Options, and the Tooltip titles Preview (a bordered box with no label would read as a second text field); Color's Opacity and Effects, and the Tooltip's Text, Behaviour and More, are named by their controls and have none. The flyout is 320px wide (480px for the Tooltip tile) and is never wider than the space between the field pane and the worksheet's right edge (`placeFly`), so it does not run off a narrow window.
  - The calculation and field-choices editors opened from a pill stay inline under the lanes.
- **Each tile's flyout holds its own settings** ([D155](../../decisions/decisions-marks.md#d155--every-marks-tile-opens-its-own-controls-the-color-flyout-generalised)), in sections named only for screen readers; the field slot opens the first. All twelve share the layout: Drop Field Here a full-width dashed row that takes a dropped field (no list), a hairline between sections, focus back on the control that changed. Which controls show for a chart type is `Dashboard/marks-flyout-model.js` (`flyoutSections`; Color: `colour-flyout-model.js`), so a tile with nothing for the type shows the slot alone, and a tile with a control is never dimmed.

  | Tile | Section: controls |
  |---|---|
  | Color | Color, Opacity, Effects ([The Color flyout](worksheet-marks-colour.md#the-color-flyout), [D151](../../decisions/decisions-marks.md#d151--the-color-tile-opens-the-colour-controls-format-keeps-the-rest)) |
  | Size | Size: a meter for every chart type with elements to size (Marker size in px on points and lines; Size as a percentage on bars, pie, funnel, gauge, Sankey, box plot, [D160](../../decisions/decisions-marks.md#d160--the-size-meter-sizes-the-elements-of-every-chart-type-that-has-any)), Edit Sizes (with a Size field drawn) |
  | Shape | Shape: Marker shape (line, area, combo), Shape bins (a measure on Shape), Edit shapes… (a Shape dimension: the Edit Shape dialog) |
  | Label | Label: Show mark labels (charts); Label Appearance (Text, Font, Alignment, Position), Marks to Label and Allow labels to overlap other marks, each offered by chart type and disabled until a label is drawn ([D169](../../decisions/decisions-marks.md#d169--the-label-flyout-follows-tableaus-label-card-show-mark-labels-label-appearance-text-font-alignment-marks-to-label-options)) |
  | Tooltip | the whole editor ([D173](../../decisions/decisions-marks.md#d173--the-edit-tooltip-editor-moves-into-the-tooltip-flyout-and-commits-live)): Text, Preview, Behaviour (Show tooltips, Include command buttons, Tooltip mode), More (Field formats, Fields on the Tooltip card, Reset) |
  | Path | Line: Line style, Line pattern (line, area, combo) |
  | Dates | Range: the range and comparison, A fall is good (while comparing) |
  | Pages | Playback: Speed (Slow / Medium / Fast), once a Pages field is set; Play and the page picker stay on the worksheet |
  | Detail, Angle, Filters, Drill | the slot (Filters repeats its filter cards); Tableau gives Detail and Angle no options either ([D158](../../decisions/decisions-marks.md#d158--tableaus-marks-card-controls-the-flyouts-lacked-a-size-meter-allow-labels-to-overlap-pages-speed)) |

  Marker size lights Size on a circle heatmap (not a square one); Marker shape lights Shape on a line; Line style lights Path on a combo.
- Code: `.ws-shelf--marks`; `buildTools` / `toolButton`; `markGrid` in `Dashboard/pill-options.js` chunks the slots into rows of three. `visibleTools(chartType, tools)` (`Dashboard/toolbar-rules.js`, pure) decides which are quiet; which types accept a colour measure or Size is `Dashboard/mark-channel-model.js` (`colourChannel`, `sizeChannel`); how a Size field becomes mark sizes is `Dashboard/size-scale-model.js` (below). The editor panel is `toolPanel` (`.ws-toolpanel`); `addFieldRow` draws the Drop Field Here row (a drop target; `wireFieldDrop` on the slot does the work). Icons come from `Core/icons.js`.

### Colour, Size and Shape by chart type (T03-19, T03-20, T03-21, T01-21)

Which chart types draw each channel, and what an unmet mapping says (always a hint above the chart, never an error). Rules: `Dashboard/mark-channel-model.js` (pure); the drawing is `Dashboard/chart.js`.

| Type | Colour = a measure | Size = a measure | Size = a dimension | Colour = a dimension |
|---|---|---|---|---|
| Scatter / Square / Circle | gradient or steps on the points | bubble size (zero-based, 8–36 px) | a step per member, 8–36 px | one series per member (below) |
| Bar | each bar its value's colour (several measures: [every measure's bars, with a pattern each](worksheet-marks-colour.md#a-colour-measure-beside-several-measures-stacked-and-combo)) | each bar's thickness (one measure) | a step per member | grouped series; Size draws too (below) |
| Line | markers coloured by value, the line a gradient along it (several measures: a dash and marker each) | the line's own thickness (below) | a step per member | one line per member |
| Area | the same, with the fill a gradient | each marker's size, shared by every area | a step per member | one area per member |
| Gantt | not used | each bar's thickness (below) | hint: a member step would split the one-bar-per-row layout | a bar per row and member |
| Pie / Donut | each slice its value's colour | hint: one pie has nothing to compare | hint | each slice split by member |
| Treemap | each tile its value's colour | the tile **area** | hint: area is a measure | not used |
| Text / Table | — | the cell font size (below) | hint: a measure only | extra header level (Table) |
| Stacked | each segment its row's colour, separated by a stroke | hint | hint | stacked series; Size is a hint there |
| Combo | bars and lines coloured by the row, a cue per measure | hint | hint | not used |
| Others | hint | hint | hint | not used |

- **One measure for Size on a bar** (a thickness per bar); line / area Size works with several measures. A colour measure takes any number of measures ([the cues](worksheet-marks-colour.md#a-colour-measure-beside-several-measures-stacked-and-combo)). A Size bar chart with a comparison period keeps its plain bars and says so.
- **Size beside a Colour dimension** (the split path) is drawn on bar, line and area: each (category, member) cell has its own size, from a measure's value or a dimension's step, on one scale across every member. A **bar** is then a grouped custom series per member, each bar in its member's slot of the band (the offset is computed in `variableBars`, the thickness within that slot); a **line** gets a thickness overlay per member line; an **area** sizes its markers per cell. **Stacked** says Size doesn't apply (`splitSizeNote`). Only one of Colour-as-measure and Colour-as-dimension exists, so a split never carries a colour measure. ([D108](../../decisions/decisions-dashboards.md#d108--size-a-dimension-steps-marks-edit-sizes-a-lines-own-thickness-text-size-and-size-beside-a-colour-split))
- **A colour measure replaces the palette**, and member colours (the member-colour editor is hidden in the Color flyout while a measure is on Colour; Opacity still applies). The Other bar / slice keeps its muted colour. The legend is the same gradient or stepped swatches as the scatter's (`colourLegend`), named with the measure, centre and pin notes. On these types it is display only (no draggable handles; steps do not toggle).
- **How the colours are found:** `valueColours` in `chart.js` maps each value through the legend's own range, ramp, pins, centre and steps (`positionOf`, `stepIndexOf` in `colour-scale-model.js`), so a mark and the legend agree. A value with no number takes no colour (a line stretch keeps its neighbour's).
- **Bar thickness:** a Size bar chart is a `custom` series (ECharts has no per-bar width): each bar runs from a 6 px minimum at the smallest Size value to 80 % of the category band at the largest (`barThickness`, `sizeFractions`: the data's own span; all equal = full). Tooltip, labels, click-to-filter, Other, colour measure and the selection fade work as on plain bars. The Other bar is the thinnest.
- **Gantt bar thickness (D123):** a Size measure sets each Gantt bar's thickness, by the bar rule: 6 px at the smallest value up to 80 % of the row slot at the largest (`ganttSizing`, `ganttThickness` in `gantt-model.js`; Size flyout → Edit Sizes applies, offered while a Size measure is drawn). The span is the drawn bars' own; a missing value is the thinnest bar; with a Colour split each (row, member) bar has its own thickness on one scale and the thinner bar draws above where bars overlap. Without Size the bars keep one thickness (60 % of the slot, at most 28 px). The Size legend sits under the Gantt's own legend and the tooltip has a Size line. A Size dimension is a hint (it would split the row's one bar) and adds no group-by; the length still comes from the second measure or Format → Length ([D123](../../decisions/decisions-marks.md#d123--gantt-bar-size-from-size-a-measure-sets-each-bars-thickness)).
- **Line thickness:** a straight **line** draws its own thickness, 2–12 px by the value's share (`lineWidthFor`). ECharts draws one width per line series, so a silent `custom` series (`thickLine`, id `size-width:<n>`, same name as the line so one legend entry toggles both) draws one tapered quadrilateral per segment, beneath the real line; the line keeps its markers (one size) and stays Solid (Path flyout → Line pattern is disabled with the reason: a dash cannot vary in thickness), tooltip, click, legend, analytics and colour gradient (a segment takes the colour measure's value at its far end). The overlay is not listed in the tooltip. A **stepped / jump line**, a line chart of more than 2,000 points in all (the overlay is one polygon per segment), and an **area** keep the markers' size instead (6–24 px, `markerSizeFor`; markers always shown while Size is set); a stepped line says how to get thickness back (Line style: Straight). Size flyout → Marker size is overridden by a Size field. ([D108](../../decisions/decisions-dashboards.md#d108--size-a-dimension-steps-marks-edit-sizes-a-lines-own-thickness-text-size-and-size-beside-a-colour-split) supersedes the line part of [D100](../../decisions/decisions-dashboards.md#d100--shape-stays-on-the-scatter-family-size-on-a-line-is-the-marker-size))
- **Treemap Size:** the Size measure sets each tile's area; the shelf measure is the label's second line and a tooltip row. Without Size the shelf measure is the area, as before. A parent's colour under a colour measure is the neutral grid colour behind its tiles.
- **Size legend:** a line at the chart's top right names the field and its smallest and largest value in words ("Size: sum qty (3 to 41)"; a dimension: "Size: region (APAC to US, 8 steps)"; a reversed scale adds ", reversed"), on every type that draws Size; a Table / Text says it above the table ("…, three text sizes").
- **Scatter Colour dimension:** a Colour dimension on scatter / square / circle splits the points into one series per member (the Colour dimension is the last group-by, as on bar), in palette order with a legend; the Color flyout's Edit member colours lists the members. With **Shape on a different field** each series is a pair, named "colour member · shape member" (colour by the Colour member, symbol by the Shape member; the legend lists the pairs and only highlights). With the **same field on both** it is one grouping and one legend of members. Shape alone is unchanged. A colour measure is not drawn while points are split by Shape or a Colour dimension (a hint). Code: `scatterGroups` (`result-model.js`), `renderScatterShapes`, `buildScatterShapes`.
- **Not built:** Size on pie / donut (kept as a hint: a pie per member of a second dimension would give it meaning).

### Size: a dimension, Edit Sizes, Text / Table font size (T03-20)

Pure maths: `Dashboard/size-scale-model.js` (`tests/js/size-scale.test.mjs`); the plan side is `sizeDimensionOf` / `sizeKeyIndex` in `sheet-plan.js`; the rows → steps are `sizeSteps` and `sizeGridOf` in `result-model.js`.

- **A dimension on Size** gives each member a step: members ordered by value (numbers) or locale (text), a missing member last, spread evenly from the smallest mark to the largest (one member = full size). The Size dimension is one more group-by (so bars of one category may split by member, as with Detail); it is only added where the chart draws it (scatter family, a one-measure bar, line, area). Tooltip and legend name the member. On Treemap, Text, Table, Stacked and pie / donut a Size dimension is a hint and adds no group-by.
- **Size flyout → Edit Sizes** (`format.sizeScale`, shown while a Size field is set on scatter, bar, line, area, Text or Table; a treemap's area *is* the value, so it takes no range): **Smallest size (%)** and **Largest size (%)** keep the marks inside that part of the chart's own size range (whole 0–100, smallest below largest; blank = 0 / 100); **Sizes vary** picks the span of a measure: **Automatic** is the chart's own default (bubbles From zero, everything else By range; [D120](../../decisions/decisions-marks.md#d120--edit-sizes-sizes-vary-and-a-typed-start-and-end-value)), **By range** runs from the data's smallest to largest value, **From zero** starts at zero (the span is min(0, smallest) to max(0, largest); bubbles keep their older floor of 1 on the top). **Start value** and **End value** (blank = the data's) type the ends of the span: a value below the start takes the smallest mark and one above the end the largest, so no mark is hidden, and the Size legend names them in words (`Size: sum qty (10 to 50, set)`, or `start set` / `end set` for one). **Reversed** gives the largest value the smallest mark. A dimension's steps take Smallest, Largest and Reversed only; its Sizes vary, Start and End are disabled with that reason. Each control that does nothing says why: under From zero Start is disabled ("From zero starts at zero") and so is Reversed (as in Tableau); under Automatic on bubbles Start is disabled until By range is picked. Picking From zero drops a stored start and Reversed; picking Automatic on bubbles, or typing an End there, drops a start stored where it does not apply. A sheet saved with both From zero and Reversed still draws reversed, and its disabled Reversed says so. A refused value (a start at or above the end, a non-number, beyond ±1e12; smallest at or above largest) shows a toast and the field returns to its stored value.
- **Stored** as `format.sizeScale` `{ smallest?, largest?, vary?, start?, end?, reversed?, fromZero? }`, only the parts that differ from the default (so a sheet without it round-trips unchanged and a plan with no Size is byte-identical): `vary` is `"range"` or `"zero"` (Automatic is absent), `start` / `end` finite numbers. An older file's `fromZero` boolean reads as the same mode and is kept as saved (it is never rewritten on import; the control writes `vary` and drops `fromZero`); `vary` wins when both are present. An older file holding both From zero and Reversed still draws reversed as before. On import a bad part is dropped (never clamped) and reported; a crossed smallest / largest pair resets both, a start at or above the end drops both, and a start beside From zero is dropped. Typed values beside a Size dimension are ignored by the drawing.
- **Text / Table font size:** a Size measure sets the text size of each row-by-column cell in three steps of the type scale: body (14 px), lead (16 px, `xt-fs-1`) and title (24 px, `xt-fs-2`), by thirds of the share (`textStepFor`; the classes are in `Core/core.css`, scaled in print). Totals and a collapsed header's combined cells keep the body size. The Size column is fetched but is not shown as a column (the status line does not count it, and the CSV export drops it). Edit Sizes is offered only while the chart draws the Size it holds. A Table's paged rows are shaped by the pages loaded so far.
- **Pie / Donut:** Size stays a hint ("one pie has nothing to compare its size with").

### Tooltip text (T01-19) and the tooltip modal

#### The Tooltip flyout

The Tooltip tile's flyout is **the whole Edit Tooltip editor** ([D173](../../decisions/decisions-marks.md#d173--the-edit-tooltip-editor-moves-into-the-tooltip-flyout-and-commits-live), which replaced D171's button and modal): no Drop Field Here row, no separate text box, no field chips. It is wider than the other tiles' flyouts (480px). The editor is there on every chart type; on the chart types that keep the automatic tooltip (Table, Text, KPI, Heatmap, Treemap, discrete-colour splits, Scatter with a Shape field and the other special types) the text is stored but not drawn. The **tile itself still takes a dropped field** (a `marks.tooltip` field joins the catalog the editor's Insert menu offers and the automatic tooltip's extra lines); the fields held on the tile are listed, and removable, in the editor's **More** section.

- **Placeholders:** group-by / Tooltip fields as `table.column`; measures as named in the view. The Insert menu offers only fields that resolve: group-by / Tooltip fields and the shelf measures (not Size / continuous-Colour measures).
- **Limits:** at most `LIMITS.tooltipText` = 300 characters and `LIMITS.tooltipLines` = 12 lines (client-side only).
- **Stored** on the sheet as `tooltipText` (`null` = the automatic tooltip) and saved with the workbook. `sanitizeSheet` drops over-long / non-text values with an import issue.
- **Where it applies:** `chart.js` `customTip` renders it for bar / line / area / combo (axis tooltip: every series in the hover), pie / donut and scatter-family charts.
- **Rendering:** unknown placeholders show as literal text; values use the existing value / category formatters.
- **Safety:** all HTML is built in `Dashboard/tooltip-model.js` from escaped parts only (`<script>`, quotes, `&` are escaped). User text never becomes markup.

#### The Tooltip editor

The Tooltip flyout is a `div.ws-flyedit` (`Dashboard/tooltip-editor.js`) laid out like Tableau's Edit Tooltip ([design reference](../../reference/design/references.md)). Focus goes to the first line on open. It **commits live** like the other flyouts: the text group (text, styles, field formats) 400ms after typing stops, on leaving the editor and on close; behaviour, a field format and removing a card field at once. It is built once per sheet and kept in place across the re-render a commit causes, so the caret, selection, undo steps, an open Insert list and a composition survive. Top to bottom, one section each:

- **Toolbar** (formats the lines the selection touches): **Font** (Default and the Label flyout's list: Serif, Monospace and the Microsoft Typography fonts), **Font size** (Auto, 14, 16 or 24 px), **Bold**, **Italic**, **Underline**, **Colour** (Auto or a token palette: text, muted, accent, green, amber, blue, teal, violet), **Align** left / centre / right, **Insert ▾** and **Clear formatting** (the `clear-format` Tx icon: a ✕ reads as "close"). Bold / Italic / Underline are one **Text style** group and Align one **Alignment** group; the Insert list is the shared menu and stays inside the flyout (a long field name is cut with an ellipsis, its tooltip has the whole name). The controls show the focused line's state.
- **Editor surface:** one text editor (a `contenteditable` surface with a block per line; no per-line rows, buttons or Add line). Type, press Enter for a new line, paste (always as plain text), cut, delete by character, word or line, select across lines, Ctrl+Z / Ctrl+Y undo and redo (100 steps); Ctrl+B / I / U toggle the flags; Alt+Up / Alt+Down move the caret's line (its style travels with it). A new line wears the format of the line it was split from. Each line is drawn in its own format. The toolbar acts on every line the selection touches. At most 12 lines and 300 characters: over either, nothing is committed and the error line says why (typing is never refused); closing the flyout with such a draft reverts it with a toast.
- **How it stays safe:** the browser never edits the surface. Every change arrives as a `beforeinput`, is cancelled and applied to the model (`replaceRange` in `tooltip-style.js`: text plus one style per line), and the surface is drawn again from the model. No HTML is read back, so none can be pasted in; input-method composition is the one edit the browser makes itself, and its line is read back as plain text.
- **Insert ▾:** a menu of the fields the chart offers, read **when the menu opens** (the chart can finish drawing after the editor did). A pick writes `<field>` over the selection, or at the caret. Arrow keys move in the menu; Esc closes the menu first, then the flyout.
- **Behaviour:** **Show tooltips** with the **mode** select beside it (Responsive / On hover) and **Include command buttons**, on every chart that has a hover tooltip. Each commits as it changes: the gating (`tooltipControlSpecs`) is computed from the sheet's Format, so unchecking Show tooltips disables the other two at once, and each disabled control says why on hover. See [Tooltip behaviour](#tooltip-behaviour-tooltip-editor).
- **Field formats** (a collapsed group, one row per `<field>` in the template that can be formatted):
  - A measure gets a **Number format** (View format, Auto, Compact, Currency, Percent) and **Decimals** (auto, 0-10); a date group-by (its sample parses as a Date / DateTime) gets a **Date format** (View format, Date, Date and time, Month, Year). Other group-bys get no row. "View format" = today's behaviour.
  - They reuse the worksheet Format code (`makeValueFormatter` / `makeCategoryFormatter`, `Core/format.js`), starting from the view's format (a currency symbol still applies). The preview and every chart tooltip that renders the template (cartesian, pie / donut, scatter without Shape) format from the raw value through `tipLookup` (`Dashboard/tooltip-formats.js`).
  - Stored as `tooltipFormats` `{ [field]: { number?, decimals?, date? } }`, only for fields still in the template. `checkTooltipFormats` on import: known values only, decimals an integer 0-10, at most `LIMITS.tooltipFormats` = 24 fields, names ≤ 200 characters; an invalid spec is dropped with an issue, never clamped; ignored without a template.
- **Fields on the Tooltip card:** a collapsed group listing the `marks.tooltip` fields with a remove button each; a removal commits at once.
- **Preview** (always shown, its own section): the tooltip as the chart hover draws it, from the first mark's sample values, built by the same `tooltipHtml`.
- **Reset** (the **More** section): the automatic tooltip and the default behaviour. It clears the text, styles, formats and the three behaviour settings together, so it **asks once** (`confirmDestructive`); there is no Cancel any more, since nothing is a draft.
- **Stored** as `tooltipStyle` on the sheet: a list aligned to the template's lines of `{ font?, size?, bold?, italic?, underline?, align?, color? }` (`null` / absent = default; `align: "left"` is the default and never stored). The key exists only once a line is styled, so files without styles round-trip unchanged.
- **Validated on import** by `checkTooltipStyle` (`Dashboard/tooltip-style.js`):
  - fonts only from the Label flyout's list, mapped to `var(--font-…)`; sizes only from the type scale; colours only palette keys, mapped to `var(--ink)`, `var(--accent-ink)`…, so they follow the theme. No hex; nothing user-typed reaches a `style` attribute;
  - at most 12 lines;
  - an invalid style is dropped with an issue; a style without a template is ignored.
- **Alignment is a block:** `tooltipHtml` draws a centred / right-aligned line as a `<div>` (`text-align` does nothing on an inline span) and puts a `<br>` only between two inline lines, so a tooltip with no alignment is byte-identical to before.
- **Not built:** styling a single field token or word inside a line (style stays per line, not per run), the ruler, and Tableau's **Allow selection by category** (no such feature here; the click-to-select is the selection chip's). The editor has no ruler because tooltips are not paginated.

#### Tooltip behaviour (Tooltip editor)

Three controls, in the Tooltip editor's Behaviour section (**Show tooltips**, the mode select beside it, **Include command buttons**; D121 first put them in Format, D151 in the Tooltip flyout, D171 in the modal, D173 back in the flyout), on every chart that has a hover tooltip (not a table, text or scorecard). Pure rules: `Dashboard/tooltip-behaviour-model.js` (`tooltipControlSpecs` over the sheet's format); the editor draws them; the click wiring: `tooltip-commands.js`. Decision: [D121](../../decisions/decisions-marks.md#d121--tooltip-behaviour-show-tooltips-command-buttons-and-responsive-or-on-hover).

- **Show tooltips** (`format.showTooltips`, on by default). Off: no hover tooltip and no axis pointer on any chart type, in the editor and on a dashboard widget. Marks, labels, selection and the table view are unchanged, so a value is never only in a tooltip.
- **Command buttons** (`format.tooltipButtons`, off by default). On: the tooltip is enterable and carries **Keep only**, **Exclude** and **View data** for the hovered mark. They run the selection chip's own actions (Keep only / Exclude select the mark with that action, never toggling it off; View data opens the mark's rows and leaves the selection alone). Offered on bar, stacked, line, area, combo, pie, donut and point charts whose marks select by a dimension value; not on a mark that is the Other group or a NULL, not while a drill hierarchy is active, on a calculated or date-part first dimension, on a point chart split by Colour or Shape, on a Gantt, or on a dashboard widget. Where the sheet shows they would do nothing the control is disabled and its title says why (also: "Turn on Show tooltips first"). A **date axis** is the case the sheet cannot fully decide: with Group dates set to a grain (Hour … Year) the first field is a period, not a value, so the control is disabled ("Group dates is Day … choose Exact"); with Group dates **Auto** the server decides from the data, so the control stays on with a note, and when the data was grouped the chart shows a one-line hint above it ("Command buttons are not shown: the first field's dates are grouped…"); Group dates → **Exact** always has the buttons.
- **Tooltip mode** (`format.tooltipMode`, only matters with command buttons): **Responsive** (default) keeps hover tooltips as today; a click on a mark selects it and pins its tooltip, with the buttons, until Esc, a click on empty chart, the mark clicked again, the selection chip's clear, a command, or any redraw. While pinned, other marks show no hover tooltip. **On hover** puts the buttons in every hover tooltip.
- **Reaching the tooltip:** it is placed once per hovered mark, a few pixels from where the pointer entered, and hides 400 ms after the pointer leaves (the pointer may cross to it meanwhile).
- **Buttons are real `<button>`s with text**, from fixed labels and a whole-number mark index; a delegated click listener on the chart host reads `data-tt-cmd` / `data-tt-idx` (no inline handler, no user text in the markup). They are pointer-only extras: the keyboard and screen-reader route to the same actions is the selection chip.
- **Not built:** Allow selection by category (the modal has no such checkbox), Group Members, Create Set ([backlog](../../development/backlog/charts-and-formatting.md)).
- **Stored** only when not the default: `showTooltips: false`, `tooltipButtons: true`, `tooltipMode: "hover"`; an unknown value is dropped and reported on import, never coerced ([data-model.md](../../reference/data-model.md)). The PNG / SVG export never contains a tooltip.

### Marks rules

- Extra measures never become chart series. With no marks set, the plan is byte-identical to a plain shelves plan.
- **Colour split needs one measure:** multi-measure + a Colour *dimension* on bar / stacked / line / area → a hint (a colour *measure* takes several). Types outside `COLOR_USES` (combo, treemap, KPI and the rest) show a note and ignore a Colour *dimension*; the scatter family and pie / donut take it as a group-by.
- Colour × category combinations are still capped by the query `LIMIT`.
- Every unmet mapping shows a **hint, not an error**.

## Member colours and palette order (T01-20, T03-33)

### Member colours

- **Editing.** **Edit member colours** in the Color flyout lists the members the drawn chart colours by a discrete field: Colour-shelf members on bar / stacked / line / area / scatter / pie / donut (several fields: the combinations), pie / donut slices, and the categories of a single-measure bar whose Colour field is its own axis field ([D154](../../decisions/decisions-marks.md)).
  - The control is one button, **Edit member colours…**, disabled until such a chart is drawn. It opens a dialog ([D161](../../decisions/decisions-marks.md#d161--edit-member-colours-is-a-landscape-dialog-a-colour-picker-left-the-members-right-saved-once)): a landscape card split at the golden ratio (38.2 % : 61.8 %). The left pane is the picker: **palettes**, each under its title with a hairline between them — the generated **Default** (a sample of its first 24 colours) and any palettes the workbook holds ([D165](../../decisions/decisions-marks.md#d165--the-workbook-can-hold-imported-colour-palettes-listed-under-titles-beside-the-generated-default)) — then one **custom colour** (a swatch that opens the colour picker, and a `#rrggbb` field: a whole valid hex is staged as it is typed, **Enter** or closing the picker sets it and moves on, anything else is refused with the reason). **Create palette…** ([D166](../../decisions/decisions-marks.md#d166--create-palette-replaces-import-palette-a-palette-is-made-in-a-dialog-not-read-from-text-or-a-file)) is pinned at the bottom of the left pane, full width, so it stays in reach however many palettes there are (the palettes and the custom colour scroll above it). Swatches are smaller and listed by ascending hex value; no outline marks the chosen one, its tick does. **Clicking a palette's title applies it to every member** in list order, repeating from its first colour when members outnumber colours (staged; it reads as applied with a tick when every member holds what it would give); the Default's title is Reset all. Create opens a small **Create palette** dialog on top: a name, then a row of colours in the order they are made (the order Apply uses; not sorted), a **+** that adds a colour, and the chosen colour's picker and `#rrggbb` field with a ✕ to remove it (one colour always stays). **Create** is disabled until the palette is valid: a name (unique among the palettes the dialog holds now, at most 40 characters, not "Default"), 1–24 colours; at 12 palettes the button is disabled and says why. Esc, ✕ and Cancel close that dialog only; Create stages the palette in the Edit member colours dialog. A palette cannot be edited or reordered once made: remove it and create it again. A palette is removed with the ✕ beside its title (no confirmation: it is a draft until Save). The right pane lists the drawn members (a swatch in the same shape as the left pane's, name, hex and a **Reset** icon button once the member has a colour of its own). A member without one shows **the colour the chart draws for it**, so the dialog is the one place that shows every member's colour. One member is selected (the first on open): click a swatch to colour it, and the selection moves to the next member (the last stays), so a run is coloured by clicking swatches; the selected member's current colour is ticked. **Reset** and **Reset all** hand a member back to its generated colour. Above 8 members a **Search members** box filters the list by name. A palette is only a source of colours: what a member is given is stored as its own colour, so removing a palette recolours nothing. The header (Color icon, title, ✕) and the footer are the Color flyout's recessed bands. Keyboard: the member list is one tab stop (Up / Down select, **Delete** resets). Below 720px the panes stack.
  - Nothing reaches the chart until **Save** (footer, with **Cancel** and **Reset all**; ✕ in the header also discards): one commit and one redraw. Created and removed palettes are saved by the same **Save** (and discarded by the same Cancel); palettes alone redraw nothing. Cancel and Esc discard. A limit error (100 members per field, key lengths) is shown in the dialog and nothing is saved.
  - **Reset all** (staged) also removes colours of members no longer in the view (which still count toward the cap).
  - Legend clicks are unchanged (highlight / select).
- **Stored** as `sheet.memberColors = { "<table>.<column>": { "<member>": "#rrggbb" } }`. This is workbook data, so a validated hex, not a token. The member key is the raw value as text (`null` has its own key), so a colour survives a change of number / date format.
- **Limits** ([api.md](../../reference/api.md#limits), client-side only): 100 members per field, 20 fields, member key ≤ 100 chars, field key ≤ 200.
  - Maps are null-prototype, so a member named `constructor` or `__proto__` is an ordinary key; an imported `__proto__` is dropped and reported.
  - Invalid entries are dropped on import and reported. Workbooks without the key load with `{}`.
- **Not covered:** a calculated field cannot be member-coloured; treemap / funnel are not wired (a scatter's Colour members are).
- **Contrast.** User colours are not adjusted. Label inks still come from `Dashboard/contrast.js` (`pickInk`), which picks the higher-contrast ink for any hex.
- **Generated colours** ([D164](../../decisions/decisions-marks.md#d164--chart-colours-are-generated-and-edit-member-colours-is-the-one-place-that-sets-them)): a member with no colour of its own is drawn in `categoryColour(its position)` (`Core/theme-model.js`): one colour per member, however many, never red, ≥ 3:1 on the surface, the same sequence in every chart. There is no palette to choose; Appearance has no chart colours.
- Code: `Dashboard/colour-model.js` (`setMemberColor`, `applyMemberDraft`, `cleanMemberColors`, `colorsByName`, `orderedPalette`, `rampStops`), `Core/theme-model.js` (`categoryColour`) and `Dashboard/member-colours-dialog.js`.

### Palette and colour scale

- **No Reverse palette (D154).** The categorical order and the ramps' ends cannot be flipped.
- **Continuous colour scale** (T03-19; Color flyout, on Heatmap and on every type that draws a colour measure: scatter, bar, stacked, line, area, combo, pie, donut, treemap):
  - **Colour scale** (`format.colorScale`: `auto` for a worksheet the user adds, `sequential` stored by every older file) — Automatic, Low → high, or Diverging ([Automatic and Use full colour range](worksheet-marks-colour.md#automatic-colour-scale-and-use-full-colour-range)): warm (`--chart-div-low`, orange) below a centre, the surface at it, cool (`--chart-div-high`, blue) above; the pair is theme-stable ([tokens.md](../../reference/design/tokens.md)) and shared with the table scale. The centre is bounded to ±1e15 (a toast refuses more; a saved one is cleared on import). Switching back to Low → high keeps the centre for later. **Colour centre** (`format.colorCentre`, blank = 0 when the data straddles it, else the middle) replaces the Colour ramp control while Diverging. The scale's ends are made symmetric about the centre (the larger distance from it, after any pins) so the middle colour sits on the centre; the legend names it in words ("centre 20"). **Diverging colours** (`format.colorPair`, default `default`) picks the two hues: Orange / Blue (the `--chart-div-*` pair), Amber / Violet or Green / Violet (each end reads its own `--chart-div-amber` / `-violet` / `-green` token (set per theme in `core.css`, tuned against the surface centre, never red, independent of the active categorical palette; never a typed hex), [D85](../../decisions/decisions-dashboards.md#d85--the-diverging-scale-picks-its-hues-from-tokens-not-a-free-hex-picker)). Reverse palette swaps the two ends. **Colour from / to are hidden while Diverging** (the ends follow the centre; a stored pin is kept but ignored, and returns with Low → high), so no "beyond range" note shows.
  - **Colour ramp** (Low → high only) — Brand (accent soft → accent), Blue, Green, Amber or Violet (the surface blended 20 % toward that categorical token, up to the token). `format.colorRamp`, default `brand`.
  - **Colour from / to** (Low → high only; `format.colorMin` / `colorMax`; blank = the data's own end) pin the ends of the scale. A value beyond a pinned end takes that end's colour (it saturates; nothing is greyed out). While a pin is active the legend reads "beyond range: end colour".
  - **Steps** (`format.colorSteps`, default 0 = Continuous): 3 to 9 discrete colour steps instead of a gradient, on either scale (heatmap and every colour-measure type). The range (data span, pins, or the symmetric diverging span) is cut into equal steps; each step takes the ramp colour sampled evenly from end to end (the first and last steps equal the ramp's ends; an odd Diverging count puts a neutral on the centre step: the surface nudged 15 % toward the ink, so it reads as a swatch in both themes; stepped heatmap cells get a `--chart-axis` hairline instead of the surface one, so a pale step is not mistaken for a gap). The outer steps are open-ended, so a pinned range still saturates; a value on a boundary belongs to the step above it; flat data (one value) is widened by 1 so the steps stay distinct. The legend becomes a row of swatches labelled with their boundaries in words ("24 to 38"); the centre / "beyond range" note sits above it. A value outside 0, 3 to 9 is reset to Continuous on import and reported, never clamped.
  - The controls show on a Heatmap, and on the other types only while a numeric field is on Color.
  - A minimum not below the maximum is refused with a toast; a saved one is cleared on import and reported.
  - An unpinned heatmap uses its plain data span.
  - Table cell scales have their own conditional-formatting colours and are unaffected.
  - Code: `Dashboard/colour-scale-model.js` (`RAMP_CHOICES`, `SCALE_CHOICES`, `effectiveScale`, `fullRangeRamp`, `DIV_PAIR_CHOICES`, `DIV_HUE_FALLBACK`, `rampColours`, `divergingColours`, `divergingRange`, `STEP_CHOICES`, `colourStepsError`, `stepColours`, `stepBounds`, `stepPieces`, `colourCentreError`, `mixHex`, `colourRangeError`, `rangeOf`).

### Table look (T01-23)

Format → Align · Row height · Shading, in the Table and Text views only. Stored as `format.tableAlign` `auto` | `left` | `center` | `right`, `tableDensity` `standard` | `compact` | `roomy`, `tableShade` `none` | `banded` | `header` | `both`.

- **Align** sets the value cells and measure headers. Auto keeps numbers right; the "Total" header follows too.
- **Row height** sets cell padding: Compact 0 vertical (the one deliberate step outside 4 / 8 / 16 / 24, golden-rule 2), Standard 4 / 8, Roomy 8 / 16.
- **Shading:** Banded shades even body rows (subtotal and grand-total rows count in the alternation); Header shades the header cells. Both use `--surface-3`, a step that reads in light and dark.
  - Banding skips cells carrying a rule or scale (`.xt-cf`), so their tone wins. Header shading keeps each header's own ink.
- All three are classes on the table (`xt-a-*`, `xt-d-*`, `xt-s-*`; defaults add none). There is no free font, size or colour.
- Code: `Dashboard/table-style-model.js` (`tableStyleClasses`, `TABLE_*_CHOICES`).

### Table columns (T01-23)

Format → **Columns**, in the Table and Text views: pick a column, then set its own **Align** (Table setting | Left | Centre | Right, over the table-wide Align) and **Width (px)** (blank = automatic); **Reset column** clears both. Stored as `format.tableCols`: `{ [key]: { align?, width? } }`, absent when no column is set, so older workbooks open unchanged.

- **Columns** are the Rows dimensions (the left stub, keys `d0`, `d1`, …) and the measures when they run across the top (`m0`, `m1`, …). A key is a position, so renaming a field keeps its setting; reordering shelves, or removing a field ahead of it, shifts a setting to the column that takes its position. With measures down the left, only the dimensions are listed (the value columns are the Columns members). A column that no longer exists is dropped on the next change.
- **Width** is a whole number, 48–600 px (`sheet-schema.js` `TABLE_COL_MIN` / `TABLE_COL_MAX`); anything else is refused with a toast, and a saved value out of range resets to automatic with a note (at most five notes per sheet, then a count). A fixed column clips long text with an ellipsis. Once any width is set the table stops stretching to fill the pane (`xt-sized`), so a width holds; a stub cell that spans columns (a collapsed header, a total label) takes the alignment only.
- **Resize handle:** every measure header carries a vertical separator (`role="separator"`, focusable, a visible bar that turns accent on hover and focus). Drag it, or press ← / → on it (8 px; Shift = 40 px); Delete or a double click returns the column to automatic. Focus stays on the handle through the redraw. Dashboards draw the saved widths and alignments but no handle.
- Alignment rides as `xt-ca-*` classes and a width as inline px on every cell of the column, so conditional-formatting tints and totals follow it. Not built: a chosen header or row colour, fonts beyond the three stacks, chart-view alignment ([backlog](../../development/backlog/charts-and-formatting.md)).
- Code: `Dashboard/table-columns-model.js` (`tableColumnList`, `setTableColumn`, `columnLook`, `nudgeWidth`, `columnWidthError`, `cleanTableCols`), `render-table.js` (`colStyle`, `grip`), `dashboards.js` (`columnEditor`, `setColumn`); `tests/js/table-columns.test.mjs`, `tests/live/table-columns-ui.mjs`.

### Worksheet background (T01-23)

Format → Background on every chart type and on Table / Text. Stored as `format.background` `none` | `subtle` | `muted` (absent reads `none`).

- Subtle is `--surface-2`, Muted is `--surface-3`: palette tokens that follow light and dark, never a free colour. The class `ws-bg-subtle` / `ws-bg-muted` goes on the worksheet's container (worksheet view and dashboard widgets alike); None adds none.
- The chart canvas and the table are transparent, so the shade shows behind them. The class is set at the start of every run and on each draw, so loading, empty and error states carry the current shade. A PNG export of a canvas chart fills with the shade; an SVG export is not shaded.
- On Muted (the same step as table Shading) banded rows and header shading step to `--surface-2`, so Shading stays visible.
- Code: `Dashboard/background-model.js` (`BACKGROUND_CHOICES`, `backgroundClass`), set in `worksheet-view.js`'s `drawResult`. `format.background` is not in `defaultFormat()`; the workbook loader keeps it only when present, so older files round-trip unchanged.

### Worksheet font (T01-23)

Format → Font on every chart type and on Table / Text. Stored as `format.font` `default` | `serif` | `mono` (default `default`).

- A fixed list of system stacks, nothing downloaded and no font file vendored (golden-rule 10): Default is the app's `--font`; Serif is `--font-serif` (Charter, Sitka, Cambria, Georgia); Monospace is `--font-mono`. Both tokens are in `core.css`.
- It changes the family only; sizes stay on the 14 / 16 px scale.
- A chart reads the token into its text styles (axes, legend, labels, tooltip); a table takes the class `xt-f-serif` / `xt-f-mono` (the default adds none).
- KPI cards, the worksheet title and the toolbars keep the app font.
- Code: `Dashboard/font-model.js` (`FONT_CHOICES`, `fontToken`, `fontClass`); `FONTS` in `Core/sheet-schema.js`.
