# Worksheet marks — the Colour channel in detail

What the Colour slot does beyond the table in [worksheet-marks.md](worksheet-marks.md): a colour measure on several measures, the Automatic colour scale, mark opacity, several Colour fields and a Colour field on Pie / Donut. Member colours and the palette are in [worksheet-marks.md § Member colours](worksheet-marks.md#member-colours-and-palette-order-t01-20-t03-33).

## The Color flyout

Clicking **Color** opens the flyout: up to three sections split by a hairline: **Color** (opening with the field pills and Add field), **Opacity**, **Effects** ([D151](../../decisions/decisions-marks.md#d151--the-color-tile-opens-the-colour-controls-format-keeps-the-rest)). Which controls show depends on the chart type and on what Color holds (`colourFlyoutGroups`, `Dashboard/colour-flyout-model.js`), so a control never appears where it does nothing; a table gets the pills only.

| Section | Controls |
|---|---|
| Color | Colour by category (bar and scatter with no measure on Color). A measure on Color or a heatmap: Colour scale, Steps, Colour ramp (or Diverging colours and Use full colour range), Reverse palette, **Limits** (a closed disclosure: Colour from / to, or the centre). A field: Reverse palette, Edit member colours |
| Opacity | Opacity, a progress bar from 0 % to 100 % in steps of 10 (the thumb's value is read out beside the label; the change applies on release) |
| Effects | Border thickness, a progress bar over None / 1 px / 2 px / 3 px (stored as `format.markBorder` `none` / `thin` / `medium` / `thick`); Border colour (a four-swatch picker) once a border is set; Line markers (line, area, combo) |

A section with no control for the chart type is left out (with its divider). The sections carry no visible heading: the controls name themselves, and each section has an `aria-label` for screen readers.

- Reverse palette shows on every chart type, since it also reverses the default series colours.
- Format has none of these; **Line pattern**, Marker size and shape, Edit Sizes, Shape bins and Edit member shapes stay there. Format and the flyout are never open together.
- **Add field in the Color flyout** is its own full-width row under the field pills, not an item inside the dashed zone: a dotted-edge button with the plus and label centred both ways (the edge is a `::before` overlay, because `buttons.css` sets `border: 0 !important` on every button). The dashed zone holds the pills only and is absent while Color is empty (the whole field slot still takes a dropped field). Hovering Add field opens the field list as a **side menu** against the flyout's right edge: a sibling of `.ws-toolfly` (the flyout's overflow would clip a child), sharing its border line, level with the Color section, never over it; it never moves to the flyout's other side (that is the field pane, where fields are dragged from), so a narrow worksheet shrinks it from 240 px down to 120 px instead. The pointer can cross from the button to the menu (a 200 ms grace); hover does not take focus. Click or Enter opens it and focuses the search; Escape, a press outside, a pick, or closing the flyout closes it. Other flyouts keep the list inside the flyout under the zone.
- Every change rebuilds the flyout, so focus returns to the control that changed. The member list fills in after the chart draws and stays open across redraws.
- Code: `colourEditor` / `restoreColourFocus` / `fieldPicker({ side })` / `placeFly` in `Dashboard/dashboards.js`, `.ws-colourfly` in `dashboard.css`; the model above; `wireLineControls(..., ["lineMarkers"])` in `line-controls.js`. Browser checks: `tests/live/marks-colour-ui.mjs` (including the design probe) and `tests/live/colour-menu-ui.mjs` (the side menu: rects, hover, Escape, 900 / 820 / 760 px).

## One slot, two kinds of content

The Colour slot holds **one measure** (a continuous colour: a gradient or steps) or **up to three categorical fields** (a discrete colour: one colour per member). Dropping a measure replaces every field; dropping a field on a measure replaces it; dropping a field already there, or a fourth, is refused with a message (`addColourField`, `Dashboard/colour-fields-model.js`; `LIMITS.colourFields` = 3, client-side). Every field is one more group-by of the 12 a view may have (`checkAdd`, `viewCounts` in `filter-rules.js`); at that cap a Colour drop appends and is refused, it does not swap the existing field.

## A colour measure beside several measures, Stacked and Combo

A colour measure draws on bar, **stacked**, line, area and **combo** with any number of measures ([D109](../../decisions/decisions-dashboards.md#d109--a-colour-measure-beside-several-measures-on-stacked-and-on-combo)): every mark of every measure wears the colour of **its row's** colour value, and one display-only gradient legend names the measure. Colour then no longer says which measure a mark belongs to, so each measure keeps a non-colour cue (`measureCue`, `mark-channel-model.js`), used only while a colour measure is on several measures:

- **Lines and areas:** a dash (solid, dashed, dotted, dash-dot, long dash) and a marker (circle, square, diamond, triangle, starting from Format → Marker shape); the markers are always shown; the legend icon is the marker.
- **Bars and stacked segments:** a surface-coloured pattern over the bar (none for the first measure, then diagonal stripes, dots, the other diagonal, horizontal lines). The legend swatch is neutral grey with the pattern. Stacked segments of one bar are also separated by a 1 px surface stroke (unless the Color flyout's Border thickness is set).
- **Combo:** the left-axis bars take the first measure's cue, the right-axis lines (or bars or areas, per Format → Right-axis marks) the next ones.
- One measure draws as before (no cue). Size still needs a single measure on a bar.

## Automatic colour scale and Use full colour range

The Color flyout's **Colour scale** has three choices: **Automatic**, Low → high and Diverging ([D110](../../decisions/decisions-dashboards.md#d110--the-colour-scale-starts-automatic-diverging-when-the-data-crosses-zero-and-use-full-colour-range)).

- **Automatic** is Diverging (centre 0) when the colour values run from below zero to above it, Low → high otherwise (`effectiveScale`; touching zero is not crossing it). It is resolved once per drawing, against the values the scale reads (a colour measure, a heatmap's cells, a treemap's leaves), before any colour is computed. **A worksheet the user adds, or clears, starts Automatic** (`freshSheet`, `Core/store.js`); `defaultFormat()` stays Low → high, so a saved workbook, whether it stored Low → high or nothing, opens as it always did. Choosing Automatic is the only way to get it on an older sheet.
- The flyout shows the controls of the scale the drawing resolved to (Diverging colours and, under **Limits**, the centre for a diverging scale; the ramp and, under **Limits**, the range pins for Low → high); a redraw that changes the resolution refreshes the open flyout (`onColourScale` hook).
- **Use full colour range** (`format.colorFullRange`, optional; shown for a smooth Diverging scale): off (the default) is symmetric about the centre, so the larger side sets both ends and the smaller side never reaches its end colour; on gives each side its own span: the lowest value wears the low colour, the highest the high colour, the centre colour stays on the centre. The gradient runs from the data's minimum to maximum (stops resampled so the centre sits on it; `fullRangeRamp`). It needs a centre strictly inside the data (else one side only: symmetric). Steps already wear both end colours and keep the symmetric split, so the checkbox is hidden while Steps is set.
- On an Automatic scale that resolved to Diverging the centre colour is the surface nudged 15 % toward the ink, so a mark at the centre stays visible; an explicit Diverging keeps the surface.

## Include totals (Tableau's Edit Colors check box)

Tableau's **Include totals** lives here as **Format → Conditional formatting → Include totals** on Table and Text, because a crosstab's cells take their colour scale there, not from the Colour slot: see [worksheet-table-view.md § Conditional formatting](worksheet-table-view.md#conditional-formatting-p37) ([D122](../../decisions/decisions-marks.md#d122--include-totals-in-the-colour-encoding)). The Colour slot's gradient on charts has no totals to include.

## Mark opacity

The Color flyout's **Opacity** (`format.markOpacity`, a whole percent in steps of 10, 0–100; absent = 100) on every chart type that draws coloured marks (the types that take a border, plus line, area and small multiples) ([D111](../../decisions/decisions-dashboards.md#d111--mark-opacity-multiplies-the-opacity-a-mark-already-has)). It **multiplies** each mark's own opacity (a scatter's 0.8, an area fill's 0.18, a dimmed selection's 0.35) instead of replacing it, after the selection dim, so a dimmed mark stays fainter than a kept one (`applyMarkOpacity`, `mark-opacity-model.js`). Reference lines, bands, the trend, labels, axes and legends keep full strength. A straight line drawn with a Size thickness hides its thin stroke when opacity is below 100 so the overlay does not stack into a darker core; a Gantt multiplies its bar fill (not its length label); a treemap tile is drawn with an alpha colour and its label ink is picked against the tile as it shows (as are heatmap labels). The stored key is removed at 100.

## Several fields on Colour

With two or three categorical fields a mark's colour is the **combination** of its members, named "web · DE" ([D112](../../decisions/decisions-dashboards.md#d112--several-fields-on-colour-combined-members)): one series, legend entry and colour per combination, on bar, stacked, line, area, pie, donut and the scatter family (a Gantt and a Table use the first field only and say so). The fields are the last group-by keys, in order; `colourDimsOf` / `planDims(...).colourDims` (`sheet-plan.js`) list them, `colorSplitData(result, fmtCat, k)` and `scatterGroups` read the last *k* keys. The legend **highlights** a combination and selects nothing (there is no single field to filter by); a single field keeps selecting its member. Member colours (Edit member colours in the Color flyout) are keyed by the fields as a JSON array (`fieldColorKey` of `{ combined }`) and by the combination as a JSON array of the raw members (`memberRaw`), so a name that contains " · " cannot collide; the 100-character member-key limit applies to that encoding, and a combination whose field key would pass the 200-character limit (long table and column names) is refused when its colour is set, since import would drop it. On import a leading measure keeps only itself, otherwise the categorical fields are kept up to three, repeats and measures dropped, and what was dropped is reported.

## A Colour field on Pie / Donut

A categorical Colour field on a pie or donut splits **each slice into one sub-slice per member** ([D113](../../decisions/decisions-dashboards.md#d113--a-colour-field-on-pie--donut-splits-each-slice-by-member)): the slice field stays the Columns / Rows dimension, the Colour field is the last group-by, sub-slices are grouped under their slice (slices in the server's order, a slice's members as returned; `pieSplit`, `pie-split-model.js`), each member keeps **one colour across every slice**, and the legend lists the members (a click selects the member when there is one field). A sub-slice is named "slice · member" in its label and tooltip; a click selects its slice. The Top N cap counts (slice, member) groups (the Format control says "Top N (sub-slices)") and there is no "Other" remainder (that bucket needs one group-by). A Colour field that is also the slice field adds nothing (grouped once: the pie colours by slice as before). A saved pie that already had a Colour field now draws the split instead of ignoring the field (its data does not change).
