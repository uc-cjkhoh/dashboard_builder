# Decisions — the Marks card against Tableau

Lookup: [README.md](README.md). The comparison itself: [tableau-marks-comparison.md](../reference/tableau-marks-comparison.md). Edit an entry in place when it changes.

## D118 — The Marks card follows Tableau except where the app has no uploads, no maps or no contrast rule yet

- **Chosen:** the Marks card matches Tableau's Marks-card help (Color, Size, Label, Detail, Tooltip, Shape, Path) wherever the job can be done with the app's own parts. Where it cannot, it differs on purpose and says so in the interface (a hint, never an error). The differences are listed in [tableau-marks-comparison.md](../reference/tableau-marks-comparison.md); each one is either backlog work or one of the three reasons below.
- **No uploads → no custom shape palettes.** Tableau's Shape card loads image files from a repository folder. The app takes no file uploads and stores specifications only ([out-of-scope.md](../development/backlog/out-of-scope.md)), so Shape keeps seven built-in symbols and per-sheet member shapes (D115). A user-supplied image would also need the stored-colour contrast and size rules.
- **No maps → no halos and no Polygon.** Both exist in Tableau for map and background-image views; they come back with the maps item ([analytics-and-maps.md](../development/backlog/analytics-and-maps.md)).
- **No stored-colour contrast rule yet → no free palette editing.** Custom hex colours and an editable palette wait for a written contrast and saturation rule for stored colours (the palette entry in [charts-and-formatting.md](../development/backlog/charts-and-formatting.md)). Until then colour choices are tokens and 24 fixed swatches.
- **Not a Tableau clone:** where the same job is done differently, the app keeps its own control (Label position, Automatic colour scale, per-line tooltip styling). A feature is added to close a gap only when a backlog entry says so.
- **Rejected:** copying Tableau's dialogs one for one (it would add controls that do nothing on these chart types, against the gating rule of [D108–D117](decisions-dashboards.md)); treating the comparison as a to-do list (the backlog is the only to-do list).

## D119 — Line pattern and Line markers on the Marks card

- **Chosen:** Format → **Line pattern** (Solid, Dashed, Dotted) and Format → **Line markers** (Automatic, All, None) on Line, Area and Combo lines, in the Tableau Marks card's own words. Both are stored on `format` only when they differ from the default (`linePattern` `dashed` | `dotted`; `lineMarkers` `all` | `none`), so older workbooks open unchanged and a sheet that never set them draws byte for byte as before; an unknown saved value is dropped and reported, never clamped. One pure rule serves the drawing and the panel (`line-style-model.js`, `line-marker-model.js`), so a control is offered exactly where it does something and otherwise **disabled with its reason as the title**.
- **A dash that already means something keeps its meaning.**
  - A measure cue (a colour measure beside several measures) names its line: the cue wins and Line pattern is disabled with that reason. The cue's markers likewise win over None.
  - A comparison line stays dashed and faded; beside a Dashed or Dotted main line it takes a dash-dot, so the two differ without colour.
  - Reference lines and bands are analytics, never patterned. The trend line stays dotted, but beside a Dotted main line it takes the same dash-dot as a comparison line (it also has its end label), so the two differ by more than colour.
- **A straight line whose thickness follows Size stays solid, as in Tableau** (a dash cannot vary in thickness): the thickness is drawn as polygons (D108). The bound is 2,000 points in all the lines together; the drawing records the count it drew per sheet (`noteLinePoints`) and the panel reads it, so both apply the same `lineSizeMode`. Past the bound, and on a stepped line or an area, Size sizes the markers, so Line pattern applies there.
- **None never hides a value.**
  - A lone value (no neighbour on either side: a one-point line, a point between gaps) keeps its dot.
  - A mark that carries a label keeps a clear anchor: the dot is filled and bordered `transparent`, not given opacity 0, which a label sitting on it would inherit (seen in the browser check). Hover restores the dot's own fill and border, and the series' mark opacity still applies.
  - A marker that is data stays: Size on a stepped line, an area, or a straight line past 2,000 points (D108) and a measure's cue marker win over None, and Line markers is disabled with that reason. A sheet never drawn counts as within the bound.
  - The tooltip and the axis pointer are unchanged.
- **Marker size and Marker shape are not disabled under None:** a lone value and a hover dot still use them. The Line markers control's title says what None does to them.
- **All** pins every dot (`showAllSymbol`), because ECharts otherwise thins dense symbols, and a big canvas chart skips LTTB sampling for it (sampling would drop points and their markers; the 5,000-group cap bounds the cost). Automatic is untouched, including its own gap (a lone value past 60 points shows no dot).
- **Selected points (Tableau) is not built:** a line chart does have a selection (a click on a mark, or the dashboard's), but the chart is handed the selected marks only while Label marks is Selected (`labelMarksSpec`). Selected markers would need that selection passed through for Line markers on its own, on every cartesian render path; it stays in the backlog as that plumbing.
- **Rejected:** a custom polygon drawing for dashed thickness; patterning the cue lines (it would erase what names each measure); hiding the controls instead of disabling them (the user could not learn why); storing the defaults (every saved workbook would change).

## D120 — Edit Sizes: Sizes vary and a typed start and end value

- **Chosen:** the From zero checkbox becomes a **Sizes vary** drop-down (Automatic, By range, From zero), and a measure gets an optional typed **Start value** and **End value**, as in Tableau's Edit Sizes dialog. Stored as `format.sizeScale` `vary` (`"range"` / `"zero"`), `start`, `end`, only when set.
- **Automatic is today's per-chart default, not Tableau's data-driven rule.** Tableau picks From zero when the data does not cross zero. D110 could make the colour scale's Automatic data-driven because new sheets start with `auto` in `defaultFormat`, while an absent value still reads sequential. `sizeScale` stays off `defaultFormat` ([D108](decisions-dashboards.md#d108--size-a-dimension-steps-marks-edit-sizes-a-lines-own-thickness-text-size-and-size-beside-a-colour-split)): a sheet without it round-trips unchanged and every saved sheet's absent setting already means the chart's own default (bubbles from zero, everything else by range). Adopting Tableau's rule would redraw those sheets, and it would make the sizes jump when refreshed data starts crossing zero. So Automatic stays the per-chart default and a data-driven rule is not built. An older file's `fromZero` boolean reads as the same mode (`true` = From zero, `false` = By range), is kept as saved on import, and loses to `vary` when both are present; the control writes `vary` and drops `fromZero`.
- **A typed end saturates, never hides.** A value below the start takes the smallest mark size and one above the end the largest (through Smallest / Largest and Reversed, so a reversed scale gives the below-start value the largest mark). All-equal data keeps full size and is never reversed unless an end is typed. A typed end replaces the bubble floor of 1. A start is not used where the span starts at zero (explicit From zero, or Automatic on a bubble chart): its control is disabled with that reason. Typed values apply to a measure only; beside a Size dimension they are ignored and disabled.
- **Reversed is off under an explicit From zero, as in Tableau.** The control is disabled with the reason, and picking From zero drops a stored Reversed and start. An older file holding both still draws reversed exactly as before (import keeps it; only the control shows the reason). Reversed stays available under Automatic on bubbles, which are From zero by default, so no existing bubble chart loses it.
- **Limits:** start and end are finite numbers within +/-1e12 (`SIZE_VALUE_LIMIT`), start below end. On import a non-number or out-of-range value is dropped and reported, a crossed pair drops both, a start beside From zero is dropped; nothing is clamped. The server never sees the setting (client-only).
- **The legend names the ends in words:** `Size: sum qty (10 to 50, set)`, `start set` or `end set` for one typed end; the legend shows the typed end, not the data's.
- **Rejected:** a Sizes vary choice for a dimension (its members are steps); Tableau's two checkboxes ("Start value in legend" / "End value for range") as separate switches (a blank field already means off).

## D121 — Tooltip behaviour: Show tooltips, command buttons, and Responsive or On hover

- **Chosen:** three Format controls on the charts that have a hover tooltip: **Show tooltips** (on by default), **Command buttons** (off by default) and **Tooltip mode** (Responsive by default, or On hover), in Tableau's words. Stored on `format` only when not the default (`showTooltips: false`, `tooltipButtons: true`, `tooltipMode: "hover"`), validated like the other format parts (an unknown value is dropped and reported on import, never coerced). Unset = the tooltip it always was: a golden fixture over 23 chart builders proves the option and the formatter output are identical.
- **Show tooltips off** removes the tooltip and the axis pointer on every chart type, applied once to the built option (`applyTooltipBehaviour`, so a dashboard widget obeys it too). A value is never only in a tooltip: data labels, the selection and its chip, View data and the table view stay, which is why switching the tooltip off is safe.
- **Command buttons** are Keep only, Exclude and View data, with the same effects as the selection chip: no filter logic was added. The tooltip is made enterable; because ECharts moves a tooltip with the pointer (so reaching it moves it, and on an axis tooltip crossing the next category swaps its content), it is anchored once per hovered mark a few pixels from where the pointer entered, and hides 400 ms after the pointer leaves. A real-mouse browser check shows the pointer reaching it on bar, line, point and pie.
  - Only where a click selects by a dimension value (`BUTTON_TYPES`: bar, stacked, line, area, combo, pie, donut, point), in the editor, on a mark with a real value (not Other, not NULL), and not under a drill hierarchy, a calculated or date-part first dimension, or a point chart split by Colour or Shape. A dashboard widget's marks cross-filter, which is not Keep only, so it gets none. Where they would do nothing the control is disabled and says why.
  - **Gantt is left out:** one row can hold several bars (colour members) and its tooltip index is a bar, not a row, so the tooltip cannot address a row the way its click does. It keeps its hover tooltip and click.
  - **Group Members and Create Set are not built:** the app has no sets, and a group needs a member list chosen first. **Allow selection by category** is not built either: a tooltip line would need to know which of its fields is a discrete dimension and select that one, a separate piece of work. Both stay in the backlog entry.
  - Buttons are `<button type="button">` with text (never colour alone), built from fixed labels and a whole-number mark index; the click is one delegated listener on the chart host reading `data-tt-cmd` and `data-tt-idx`. No inline handler, and no user text reaches the markup (a member named `<b onclick=x>` is escaped in the tooltip text). Keyboard and screen-reader users keep the same actions on the selection chip; the buttons are a pointer shortcut.
  - **Keep only and Exclude always set the action** rather than toggling it, so choosing one from a tooltip of an already selected mark does not clear it. **View data** reads the mark's rows without changing the selection.
- **Responsive and On hover.** On hover puts the buttons in every hover tooltip. Responsive keeps hover tooltips as today and **pins** the tooltip of the mark a click selects, with the buttons.
  - The pin is **one-shot**: the click leaves a transient mark (`takePin`) that the next drawing consumes, so a Format edit, undo or returning to the tab never re-opens a tooltip, and nothing is saved in the workbook.
  - While pinned the tooltip uses `triggerOn: "none"` and `alwaysShowContent`, so hovering another mark neither replaces it nor leaves a button-less tooltip stuck on screen; other marks show no hover tooltip until it is dismissed. Dismiss: Esc, a click on empty chart, the same mark again (it deselects), the chip's clear, a command, or any redraw. ECharts ignores a hide while `alwaysShowContent` is set, so dismissing first gives the pin up and restores hover tooltips.
- **Rejected:** pinning from the stored selection (it would re-open on every redraw); `hideDelay` alone (the pointer cannot reach a tooltip that follows it); a custom popover outside ECharts (it would duplicate every chart type's tooltip text); buttons on a dashboard widget (they would mean something different from the chip there).
