# Backlog: Edit SQL and the MySQL syntax

What the Edit SQL dialog ([sql-editor.md](../../concepts/data-source/sql-editor.md), [query-sources.md](../../concepts/data-source/query-sources.md#custom-sql-on-a-card)) and its MySQL ⇄ ClickHouse switch ([sql-syntax.md](../../concepts/data-source/sql-syntax.md), [D105](../../decisions/decisions-custom-sql.md), [D106](../../decisions/decisions-custom-sql.md#d106--mysql-syntax-in-edit-sql-translated-to-clickhouse)) still do not do. Format: [index.md](index.md#how-to-read-an-entry). Entries run by priority: **silent wrong results first, then loud failures, then gaps, then operations.**

**Measured against** ClickHouse 26.8.36.3 (the test server) with `tests/live/translate-smoke.mjs`: 379 MySQL → ClickHouse cases (the first 106, a battery of common functions with NULL, sign and case edges, and 27 from running 10 complex queries over a real table) match MySQL's documented results; of the first 19 typical ClickHouse queries 8 open in MySQL syntax and 11 in ClickHouse syntax (13 of 24 with date queries added later and the NULL order, aggregate names and formatDateTime fixed; the others open in ClickHouse by design or because of a ClickHouse-only function). There is no MySQL server, so "MySQL's result" is its documented behaviour.

## Decision to settle

- **How a saved ClickHouse query that filters on text opens.** Today it opens in **ClickHouse syntax** with a warning when its MySQL form would not mean the same (a string comparison, `IN`, `LIKE`, a division, a renamed column, a refused function): 11 of 19 typical queries. The alternative is to open them in MySQL (the requested default) and accept that an edit then makes the comparison ignore case — a one-line change in `keepsMeaning()` (`Canvas/sql-dialog.js`). New cards and anything written in MySQL are unaffected. Settle it, then edit [D106](../../decisions/decisions-custom-sql.md#d106--mysql-syntax-in-edit-sql-translated-to-clickhouse) in place.

## Silent differences (no error, different rows or values)

- **Text semantics beyond a literal comparison** (priority P1; effort L) — Partial: `=`, `!=`, `IN`, `NOT IN` against a text literal and `LIKE` ignore case as MySQL does; division by zero is NULL. Done in tier 3: `col = col` between two text columns (types asked of ClickHouse, see sql-syntax.md). Open: **grouping, sorting and `DISTINCT` on text** (MySQL treats `'A'` and `'a'` as one value; only a note says so, no rewrite), and, silently ClickHouse's behaviour, `JOIN … USING (col)`, a comparison of two expressions that are not plain columns, `<` / `>` / `BETWEEN` on text, accent-insensitivity and other collations, implicit conversions (`'1' = 1`), MySQL's SQL modes. Needs: a decision on cost, because every rewrite costs the primary key on a large table (filters can run into the 12 s limit). Spec: [sql-syntax.md](../../concepts/data-source/sql-syntax.md#limitations).
- **Translation verified on one ClickHouse version** (priority P1; effort S) — Partial: `tests/live/translate-smoke.mjs` re-runs the 31 cases and the round-trip measurement against any server (it already showed `age('hour')` is wrong on 26.8). Open: run it on the oldest ClickHouse the app must support, record the minimum version, and add it to the deploy checklist for any change to `Tools/sql_translate.py` or a ClickHouse upgrade.

## Loud failures (an error or a refusal that blocks the query)

- **MySQL-only functions and clauses still passed through** (priority P3) — Partial: tier 2 translated `STR_TO_DATE`, `UNIX_TIMESTAMP`, `LAST_DAY`, `JSON_UNQUOTE` / `->>` / `JSON_VALUE`, `DATE_FORMAT`, `FROM_UNIXTIME`, `LIKE … ESCAPE`, compound intervals, `SQL_CALC_FOUND_ROWS`, hints, `STRAIGHT_JOIN` and `FOR UPDATE`, and refuses `@var`. Tier 3 added the common-function battery (`CONCAT_WS`, `UPPER` / `LOWER`, `REGEXP*`, `ROUND`, `GREATEST` / `LEAST`, bit operators, `GROUP_CONCAT`, `FIND_IN_SET`, `FIELD`, `ELT`, `STRCMP`, `SHA*`, week-day and name functions, `ADDDATE` …) and refuses `FORMAT`. Open, passed to ClickHouse as written (it may refuse them or read them differently): every function not listed in [sql-syntax.md](../../concepts/data-source/sql-syntax.md#limitations) — `OCT`, `CONV`, `TIME_TO_SEC` / `SEC_TO_TIME`, `ORD`, the `JSON_*` helpers (`JSON_LENGTH`, `JSON_VALID`, `JSON_TYPE`, `JSON_CONTAINS_PATH`; they fail loudly: ClickHouse has no function of that name), spatial and full-text functions, `CONVERT(x USING …)`, `INSERT` / `REPLACE` text functions. Each needs a mapping or a refusal with a reason and an exact-output test plus a smoke case.
- **Stricter than MySQL, with a note or a refusal** (priority P3) — Open: `STR_TO_DATE` needs zero-padded `%i %s %S`, and `%m %d %H %h %I` when another code touches them (`'%Y%m%d'`); a code between separators reads one or two digits (`'2024-3-5'` works); it refuses `%y %D %f %U %u %V %v %w %X %x` and a format with only a time (MySQL answers a TIME); MySQL's behaviour for extra trailing text is not verified; a nested JSON object prints without MySQL's space after the colon; `JSON_VALUE … RETURNING`, wildcard and slice paths are refused; `||` stays refused on purpose (OR in MySQL, concatenation in ClickHouse) unless a per-query choice is added; a fractional interval amount and `*_MICROSECOND` units are refused.

## Gaps on a custom-SQL card

- **Reads over a custom-SQL card run the query several times** (priority P3) — Open: the histogram reads the derived table three times (min, max, buckets) and a join check's per-end `LIMIT` bounds the query's output rows, not the query; both are bounded only by the time limit. A profile of an aggregating or joining query can describe a cut-off input (`max_rows_to_read` with `break`) while `sampled` stays false, as for a view. Not tested over real HTTP: the .NET tests call the gateway and the rules directly, the browser test mocks `/api/*`.
- **Union and unpivot cards** (priority P3) — Open: Edit SQL is disabled on them (they are built from their dialogs and have no SQL of their own).
- **Small rules** (priority P3) — Open: re-saving an old MySQL card re-translates it, and the aggregates are now written `count(…)` / `sum(…)`, so an unaliased `COUNT(*)` column is renamed `count()` (a worksheet field bound to the old name is not re-checked; alias the column to keep it); `CH_ONLY_SYNTAX` also refuses a column that is literally named `format`, `sample`, `final` or `global` when shown as MySQL (safe, it just opens in ClickHouse syntax); a table without a `db.` prefix resolves against the connection's default database; a new query must keep the columns the card's relationships use, but their types are not re-checked; the inner query is bounded only by the 12 s limit and the outer `LIMIT` (no `max_rows_to_read`).

## Round trip and the ClickHouse → MySQL display

- **Round-trip false alarms** (priority P2; effort M) — Partial: a query written in ClickHouse opens in MySQL only when the way back reports no meaning-changing repair, ClickHouse accepts it with the same columns, and `EXPLAIN SYNTAX` reads both texts the same way ([sql-syntax.md](../../concepts/data-source/sql-syntax.md#the-round-trip-check)). Fixed: a plain `ORDER BY` (the `CASE` NULL key is turned back into ClickHouse's default), `count()` → `COUNT()` (aggregates keep their lower-case spelling), `formatDateTime` (now `DATE_FORMAT`). Still opens in ClickHouse syntax, by design: a text filter (`=`, `IN`, `LIKE` against text) and a division, because their MySQL form really means something else on the way back (the decision above), `currentDatabase()` → `CURRENT_DATABASE()` (sqlglot's name, not MySQL's `DATABASE()`), and anything with a ClickHouse-only function.
- **ClickHouse-only syntax shown as MySQL** (priority P3) — Mostly done: the display now refuses what MySQL has no form for, by name (`toDate() is a ClickHouse function with no MySQL form`), so the dialog stays in ClickHouse syntax with that reason. Open: the list of MySQL function names (`MYSQL_FUNCTIONS` in `sql_translate.py`) is a hand-written allowlist, so a valid but unlisted MySQL function is refused too (safe, never wrong); common ClickHouse functions with an obvious MySQL twin (`toDate` → `DATE`, `toYear` → `YEAR`, `uniq` → `COUNT(DISTINCT …)`, `countIf` → `SUM(CASE …)`) are not mapped, so queries using them open in ClickHouse syntax.

## Operations

- **The translator process** (priority P3; effort M) — Open: it needs Python 3 on the server (without it MySQL syntax is switched off, 503); each conversion starts a process (about 0.1–0.4 s; at most 4 at once, 10 s limit), so typing in MySQL syntax is slightly delayed — a long-lived worker would remove the start-up; Python writes `__pycache__` beside the vendored library; sqlglot is pinned at 30.31.0 and upgraded by hand ([live-service.md](../../operations/live-service.md#sql-translator-mysql-syntax-in-edit-sql)); a stored query does not change when the translator is upgraded until the card is saved again.
- **Fidelity details** (priority P3) — Open: MySQL 5.7 / 8.4 / MariaDB are not told apart; the auto-formatter's dialects differ slightly from the translator's (and can print `x:: String`); a ClickHouse refusal of a translated query has no marker (its positions belong to the other text), and a query with a `/* */` comment cannot be marked in ClickHouse syntax either; one query of at most 10,000 characters.
- **Editor** (priority P3) — Open: the editor script (240 KB) loads on first use and the formatter (320 KB) on the first Format; if they cannot load, a plain text area with no highlighting, folding or checks takes over; Tab indents (Ctrl+M switches it to move focus).

## Built, not backlog

Recorded here so nothing is re-opened by mistake: `LAG` / `LEAD` / `NTH_VALUE` give NULL for a missing row (`toNullable`, change `window-null`), `CUME_DIST` written in lower case, `LPAD` / `RPAD` of a number and by characters, `TIMESTAMPDIFF` second / minute / hour exact on sub-second columns (microsecond difference), no `nullIf` around a non-zero literal divisor, outer-join NULLs inside a card's own SQL (`join_use_nulls` on the connection), code 63 passed to the user, MySQL 8 window functions shown in the ClickHouse → MySQL display (2026-11-13, found by 10 complex queries over `mnp_qsdb.tdr_local`); View data, column profile, the histogram and *Check this join* over a custom-SQL card, and the key-kind refusal on Save; `||` refused; `DATEDIFF`, `TIMESTAMPDIFF` (whole units; hours through elapsed seconds because `age('hour')` is wrong on 26.8; microseconds), `DATE_ADD` / `DATE_SUB` (column amounts, compound units as one interval, text dates), `DATE_FORMAT` / `FROM_UNIXTIME` with every format code (sqlglot's own output printed minutes as the month name), `STR_TO_DATE`, `UNIX_TIMESTAMP`, `LAST_DAY`, JSON scalars, `LIKE` → `ILIKE` and `LIKE … ESCAPE`, text comparison rewrite, the common-function battery (see sql-syntax.md), `DIV` by zero, the dropped clauses, `@var` refused; the three-part round-trip check; `DESCRIBE TABLE (subquery)` and `EXPLAIN SYNTAX` confirmed on the real server.
